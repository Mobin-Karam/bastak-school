# Security policy / سیاست امنیتی

[English](#english) · [فارسی](#فارسی)

## English

Please do **not** report a suspected security vulnerability in a public GitHub issue, discussion, pull request, or chat message containing exploit details.

1. Use the repository's private security-advisory reporting channel when it is enabled.
2. If private reporting is unavailable, contact the repository maintainer through the owner contact shown on GitHub and request a private channel before sending technical details.
3. Include affected version/commit, impact, reproduction steps, and any proposed mitigation. Do not include real credentials, production data, or private keys.
4. Allow maintainers time to reproduce, assess impact, and prepare a fix before public disclosure.

High-priority boundaries include authentication, authorization/capability checks, organization and student scoping, CSRF, validation, file upload, restore, import/export, realtime, notifications, and secret handling.

## فارسی

لطفاً آسیب‌پذیری مشکوک را با جزئیات exploit در issue، discussion، pull request یا گفت‌وگوی عمومی GitHub منتشر نکنید.

1. اگر کانال گزارش خصوصی GitHub برای مخزن فعال است، از همان استفاده کنید.
2. اگر گزارش خصوصی فعال نیست، از راه ارتباطی نگه‌دارنده در صفحه GitHub مخزن درخواست یک کانال خصوصی کنید و سپس جزئیات فنی را ارسال کنید.
3. نسخه یا commit آسیب‌پذیر، اثر، مراحل بازتولید و راهکار پیشنهادی را بنویسید. credential واقعی، داده تولید یا کلید خصوصی را ارسال نکنید.
4. پیش از افشای عمومی، برای بازتولید، ارزیابی و آماده‌سازی اصلاح به نگه‌دارنده زمان بدهید.

مرزهای مهم شامل احراز هویت، مجوز/قابلیت‌ها، محدوده سازمان و دانش‌آموز، CSRF، اعتبارسنجی، آپلود فایل، بازیابی، ورود/خروج داده، realtime، اعلان‌ها و مدیریت secret هستند.
