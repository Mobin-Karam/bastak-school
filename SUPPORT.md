# Support

## Where to ask

- **Bug report:** open a GitHub issue with version/commit, expected behavior,
  actual behavior, and a minimal reproduction.
- **Feature idea or product discussion:** use GitHub Discussions when enabled,
  or open an issue labeled `proposal`.
- **Security vulnerability:** do not open a public issue; follow
  [SECURITY.md](SECURITY.md).
- **Contribution help:** start with [CONTRIBUTING.md](CONTRIBUTING.md), then
  inspect the owning application's tests and public contracts.

## What support can cover

The repository supports self-hosted development and the documented public
interfaces. Community support is best-effort; no response-time or managed-hosting
commitment is implied.

## Before opening an issue

1. Search existing issues and documentation.
2. Reproduce on a current commit when possible.
3. Remove credentials, tokens, personal data, and production records from logs.
4. State the deployment profile: local, Docker Compose, or another documented
   environment.
