# Deployment and server audit

Audited 2026-10-12, baseline `ca1c972c566d13cade126e4c5475a0285a7d23cf`. Repository source, selected read-only GitHub metadata and host/container metadata were inspected before changes. Graphify graph/executable were unavailable. No secret values, private keys, production records, database contents or expanded production environment were read or printed. No production deployment, workflow dispatch, restore, firewall/Tailscale change, runner registration or configuration installer was run.

## Verified current deployment

- Public source `Mobin-Karam/bastak-school`; private control repository `Mobin-Karam/bastak-school-deploy`. Its installed server workflow matched `.github/deployment/server-deploy.yml` at audit start. Public source has **zero** self-hosted runners; private control has one online `bastak-production` runner labelled `bastak-lan`. Its user systemd service is active/enabled. This prevents public PR jobs directly selecting the production runner; control-repository access remains privileged.
- `docker-compose.production.yml` + `deployment/lan/compose.yml`, project `bastak-school`: one Nest/Fastify API and one React/Vite Admin/student surface. API runs as `node`; neither container is privileged. API data mount is named volume `bastak-school_moshaver_v2_sqlite` at `/data`. Nginx/TLS have read-only bind mounts. There is no separate current student app.
- Both production containers were healthy. API port 4001 and HTTP port 8082 bind loopback; container HTTPS binds all IPv4 interfaces at 443. Host Nginx also serves port 80: `/etc/nginx/sites-enabled/bastak` exactly matches the repository LAN redirect; a second active `/etc/nginx/sites-enabled/bastak-school` site differs and needs separate operator review. SSH listens on all IPv4/IPv6 interfaces. Production environment/private CA/server keys were 0600 and backup directory 0700 (values/key contents unread). No TCP Docker daemon listener was observed at 2375/2376. Other listeners were observed; their ownership/access policy is UNKNOWN and must not be disabled blindly.
- Tailscale is Running/Online and tailscaled active. No tailnet ACL/grants, SSH policy, Funnel/Serve configuration, router/NAT or firewall rules were verified. All-interface listeners do not prove internet exposure, and Tailscale presence does not prove private-only access. Use Docker-aware firewall review; [Docker documents published-port/UFW interactions](https://docs.docker.com/engine/network/packet-filtering-firewalls/).
- `develop` and `main` enforce administrators, strict required `CI Gate`, and PRs. Approving review count is zero. Source `lan-production` environment had a branch restriction and **no reviewer/wait protection**; private control had **no environments**. New protections in the supplied template are not activated merely by YAML presence.
- Current main CI dispatches to the private repository after successful exact main-push CI; hosted authorization checks CI path/event/repository/branch/SHA and current main. Private workflow rechecks, checks out exact source, then `scripts/deploy/lan.sh` builds mutable `latest` images on the host, snapshots SQLite and recreates containers. The existing shared flock and non-cancelling workflow concurrency serialize this path. Receipt indicates successful readiness, not comprehensive workflow correctness.

## CI and build gates

`.github/workflows/continuous-integration.yml` runs for every PR to develop/main and every push to them, without path filters. Its always-running gate requires both quality and container results to be success; skipped/cancelled prerequisites fail it. `tooling/workspace/projects.json` controls project scripts: Admin typecheck/format/lint/unit/a11y/build; API `lint` is `tsc --noEmit`, unit/integration tests and Nest production build; student-core and shared/CMB package tests. A separate API ESLint policy is not present, so do not mislabel TypeScript compilation as style lint. API contract, architecture, dependency audits, HTTP security/student/onboarding journeys and Chromium desktop layout also run. Required PR CI is hosted/read-only; no production secrets or runner are required. The two historical exact-branch, same-repository bootstrap jobs explicitly retain job-scoped Contents write for generated evidence; they are separate from the required validation gate. Main promotion must be develop from the same repository.

New `deployment-readiness.yml` uses SHA-pinned checkout/setup/upload actions and `verify-release.sh` to build commit-tagged images once, test them on isolated loopback ports and unique volumes, verify recovery, and upload `production-images-<sha>`. Quality and image validation remain separate prerequisites for `CI Gate`. An uploaded artifact alone is not release approval: private consumption requires the entire exact source CI run to succeed. Archives have checksum/manifest/image identity, but no signed external supply-chain attestation is claimed. Base image versions are constrained (Node 22.23.3 and Nginx 1.30.5), not digest-pinned; rebuilds can differ, so promote original bits and review base updates.

## Nginx and server limits

LAN TLS allows TLS1.2/1.3 with a local CA; distribution/trust/rotation needs operator ownership. `create-lan-tls.sh` is for initial/disposable provisioning, and immutable deploy only checks existing certificate expiry. Do not create a replacement CA implicitly. Host `host-nginx.conf` HTTP redirect serves the public CA file; signing keys are not public assets. API SSE proxy disables buffering and has long read timeout. SPA/PWA routes exist; upload bound is 64m at Nginx, which does not prove API binary parser/body-limit compatibility. Security headers are not inherited into locations declaring their own add_header; CSP/HSTS policy is not fully established and must consider LAN certificate trust/PWA before rollout. No latency/load or public reachability test was conducted.
